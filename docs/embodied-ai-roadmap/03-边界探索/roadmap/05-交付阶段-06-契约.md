# 05-交付阶段 06 契约

## 本节目标

把阶段 03 的探索能力收束成阶段 06 任务状态机可以依赖的契约。

## 为什么现在做

后续任务状态机会同时处理探索、视觉发现、停止或靠近旗帜。它不应该关心 frontier 的栅格分组细节，只需要知道如何启动、取消和解释探索结果。

## 契约一：探索目标由 frontier_explorer 自己选择

阶段 06 不需要向 explorer 提供 waypoint。第一版 explorer 的输入是：

```text
/map
map -> base_link
/navigate_to_pose action server
```

输出是对 `/navigate_to_pose` 的 goal 请求。

## 契约二：发现旗帜时取消当前 Nav2 goal

视觉发现事件出现后，任务状态机应该取消当前 `/navigate_to_pose` goal，而不是等待 frontier 完成。

取消不应被记录成 frontier 失败。取消表示任务目标改变；失败表示该 frontier 暂时不可达。

## 契约三：探索失败不是任务失败

当某个 frontier 被拒绝、失败或超时时，explorer 会冷却这个 key 并继续找其他候选。

阶段 06 只有在长期没有候选、地图没有继续扩展或超过任务级超时后，才应该考虑切换到“探索耗尽”或“人工介入”状态。

## 契约四：探索完成判定仍是后续工作

当前阶段只提供 `no usable frontier candidate found` 日志。它不是稳定的状态机接口。

阶段 06 如果需要严格状态，应该新增明确 topic 或 service，例如：

```text
/exploration/status
```

但这不属于阶段 03 的承诺范围。

## 阶段 03 解锁内容

阶段 03 解锁：

- `06-任务状态机` 的探索动作入口。
- 视觉发现后取消探索 goal 的集成路径。
- 后续探索状态 topic 或 service 的设计依据。

阶段 03 不解锁：

- 视觉旗帜检测。
- 旗帜坐标估计。
- 端到端“找到旗帜即停止”的任务流程。

这些分别属于阶段 04、05 和 06。
