# 04-验证探索闭环

## 本节目标

用分层命令证明阶段 03 不是只写了节点文件，而是真的能构建、单测、启动，并在仿真里通过 Nav2 执行 frontier goal。

## 为什么现在做

frontier exploration 牵涉 `/map`、TF、action server 和 Nav2 lifecycle。只跑单测不能证明 runtime 接通；只跑仿真又很难定位算法错误。所以本节按从轻到重的顺序验证。

本节需要参考：

- `../evidence/usage.md`
- `../evidence/validation-log.md`

## 第一步：静态编译

```bash
source .vscode/project-terminal-init.sh
python3 -m py_compile \
  src/kibot_one_control/kibot_one_control/frontier_core.py \
  src/kibot_one_control/kibot_one_control/frontier_explorer.py \
  src/kibot_one_control/launch/frontier_exploration.launch.py
```

通过条件：命令退出码为 `0`。

## 第二步：核心算法单测

```bash
PYTHONPATH=src/kibot_one_control \
  python3 -m pytest -q src/kibot_one_control/test/test_frontier_core.py
```

通过条件：

```text
3 passed
```

这些测试覆盖：

- unknown cell 与 free cell 相邻时能生成 frontier。
- goal 落在 free-side centroid。
- 小 frontier 和过远 frontier 被过滤。
- 冷却期内的 frontier 不会再次选择。

## 第三步：构建 package

```bash
colcon build --packages-select kibot_one_control
source install/setup.bash
```

通过条件：

```text
Summary: 1 package finished
```

## 第四步：launch 参数冒烟

```bash
ros2 launch kibot_one_control frontier_exploration.launch.py --show-args
```

通过条件：

- 能看到 `frontier_exploration.launch.py` 的参数。
- 能看到阶段 02 Nav2 launch 透传出的参数。
- 没有 `PackageNotFoundError` 或 launch Python 异常。

## 第五步：不启动仿真的节点冒烟

```bash
timeout 8s ros2 launch kibot_one_control frontier_exploration.launch.py \
  start_sim:=false start_slam:=false start_nav2:=false check_runtime_deps:=false
```

通过条件：

- `frontier_explorer` process started。
- 退出码是 `124`，表示被 `timeout` 正常截断。
- 没有 Python traceback。

## 第六步：短时完整仿真

```bash
timeout 35s ros2 launch kibot_one_control frontier_exploration.launch.py use_rviz:=false
```

短时仿真中应能观察到类似日志：

```text
frontier_explorer: sending frontier 7:11 at (0.56, 0.06)
bt_navigator: Begin navigating ...
controller_server: Reached the goal!
bt_navigator: Goal succeeded
frontier_explorer: frontier goal 7:11 succeeded
frontier_explorer: sending frontier 8:18 at (0.64, 0.40)
```

通过条件：

- Nav2 lifecycle 进入 active。
- explorer 至少发送一个 frontier goal。
- 至少一个 frontier goal 返回 succeeded。
- timeout 后清理残留 Gazebo / ROS2 进程。

## 失败判读

- 早期出现 `Action server is inactive. Rejecting the goal.` 不一定失败；如果后续 active 后能重新发送并成功，说明冷却逻辑生效。
- 如果 `frontier_explorer` 没有候选，检查 `/map` 是否有未知区域与 free 区域交界。
- 如果 goal 发送后一直失败，先把 `max_goal_distance` 调小，确认目标是否局部可达。

## 本节小结

验证通过后，阶段 03 可以交付给任务状态机：它已经能从地图中选择 frontier，并通过 Nav2 执行探索目标。
