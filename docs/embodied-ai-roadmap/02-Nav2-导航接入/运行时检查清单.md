# 阶段 02：运行时确认清单

## 使用目的

本文件用于记录 Nav2 接入过程中的运行时事实。

阶段 02 强依赖 TF、topic、lifecycle 和 action 状态，因此不能只靠源码静态判断。

## 环境准备

推荐先激活项目 ROS2 环境：

```bash
source .vscode/project-terminal-init.sh
source install/setup.bash
```

如尚未构建：

```bash
colcon build
source install/setup.bash
```

## 推荐启动顺序

第一版推荐分终端启动，便于定位问题：

```bash
ros2 launch kibot_one_sim kibot_one.launch.py \
  world:=<kibot_one_obstacles.world.sdf 的绝对路径> \
  mode:=4 \
  start_follow_controller:=false \
  start_keyboard_teleop:=false
```

```bash
ros2 launch kibot_one_sim slam.launch.py
```

```bash
ros2 launch kibot_one_sim nav2.launch.py
```

第一版建议新增或使用 `NAV2` 模式，让 `mode_control` 不主动发布 `/cmd_vel_raw`。`cmd_vel_watchdog` 默认保留，Nav2 controller 输出 remap 到 `/cmd_vel_raw`，再由 watchdog 转发到 `/cmd_vel`。

如果 `cmd_vel_watchdog` 实际阻塞或改写 Nav2 正常速度输出，再记录关闭或调整方式。

## 前置 topic 检查

| 检查项 | 命令 | 结果 |
| --- | --- | --- |
| `/clock` 是否存在 | `ros2 topic list | grep /clock` | 通过，`/clock` 已发布 |
| `/scan` 是否存在 | `ros2 topic list | grep /scan` | 通过，`/scan` 已发布，`frame_id: lidar_link` |
| `/odom` 是否存在 | `ros2 topic list | grep /odom` | 通过，`/odom` 已发布，`frame_id: odom`，`child_frame_id: base_link` |
| `/map` 是否存在 | `ros2 topic list | grep /map` | 通过，`/map` 已发布，类型为 `nav_msgs/msg/OccupancyGrid`，`frame_id: map` |
| `/cmd_vel` 是否存在 | `ros2 topic info /cmd_vel` | 通过，`/cmd_vel` 存在；当前发布者为 `cmd_vel_watchdog`，订阅者为 `kibot_one_bridge` |

## TF 检查

| 检查项 | 预期 | 实际结果 |
| --- | --- | --- |
| `map -> odom` | 存在 | 通过，`tf2_echo map odom` 后续能持续输出 transform；启动初期曾短暂提示 frame 尚未进入 buffer |
| `odom -> base_link` | 存在 | 通过，`tf2_echo odom base_link` 后续能持续输出 transform；启动初期曾短暂提示 frame 尚未进入 buffer |
| `base_link -> lidar_link` | 存在 | 通过，静态 TF 为 translation `[0.200, 0.000, 0.165]`，rotation identity |
| `/scan` 能转换到 `base_link` | 是 | 基于 `base_link -> lidar_link` 已存在，`/scan` 的 `lidar_link` frame 可接入 `base_link` TF 链路 |

推荐命令：

```bash
ros2 run tf2_ros tf2_echo map odom
ros2 run tf2_ros tf2_echo odom base_link
ros2 run tf2_ros tf2_echo base_link lidar_link
ros2 run tf2_tools view_frames
```
