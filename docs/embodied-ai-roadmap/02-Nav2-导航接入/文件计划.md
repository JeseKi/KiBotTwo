# 阶段 02：文件计划

## 文件计划定位

本文件说明阶段 02 预计读取、新增、修改哪些文件，以及哪些文件暂时不应该动。

本阶段是 Nav2 接入引导，不直接重构旧任务逻辑。

## 文档文件

本阶段文档：

- `路线图.md`：阶段路线、边界和实施顺序。
- `验收条件.md`：功能完成标准。
- `文件计划.md`：文件组织和改动边界。
- `运行时检查清单.md`：运行时检查和调试记录。
- `接口契约.md`：阶段 03 调用 Nav2 的接口契约。
- `记录与复盘.md`：决策、已确认事实和遗留风险。

## 推荐新增文件

第一版建议继续使用 `kibot_one_sim` 承载导航 bringup：

| 文件 | 作用 |
| --- | --- |
| `src/kibot_one_sim/launch/nav2.launch.py` | 启动 Nav2 bringup，加载参数，必要时接入 SLAM 或 map_server |
| `src/kibot_one_sim/config/nav2_params.yaml` | 保存 Nav2 最小参数 |
| `src/kibot_one_sim/rviz/nav2.rviz` | 可选，保存 Nav2 验证视图 |

暂不强制新建 `kibot_one_navigation`，避免阶段 02 同时承担 package 重构。

## 可能修改的文件

| 文件 | 修改原因 |
| --- | --- |
| `src/kibot_one_sim/CMakeLists.txt` | 如新增 `rviz` 目录，需要安装；`launch` 和 `config` 已安装 |
| `src/kibot_one_sim/package.xml` | 声明 Nav2 运行依赖 |
| `src/kibot_one_sim/launch/kibot_one.launch.py` | 可选：增加 `NAV2` 模式启动参数或关闭会抢占 `/cmd_vel_raw` 的旧控制节点 |
| `src/kibot_one_sim/launch/slam.launch.py` | 可选：如果 Nav2 和 SLAM 启动顺序需要统一 |

## Nav2 依赖候选

`package.xml` 中可能需要增加：

- `nav2_bringup`
- `nav2_bt_navigator`
- `nav2_controller`
- `nav2_planner`
- `nav2_behaviors`
- `nav2_lifecycle_manager`
- `nav2_map_server`
- `nav2_costmap_2d`
- `nav2_amcl`，仅静态地图定位方案需要。

实际依赖按第一版 launch 使用的 package 收敛，不为了完整列举而一次性添加所有 Nav2 包。

## 参数文件边界

`nav2_params.yaml` 第一版只应覆盖最小链路：

- `amcl` 或 `slam_toolbox` 相关选择。
- `bt_navigator`
- `controller_server`
- `planner_server`
- `behavior_server`
- `local_costmap`
- `global_costmap`
- `lifecycle_manager`

可以先使用 Nav2 默认插件，优先保证 frame、topic 和 lifecycle 正确。

## 启动文件边界

`nav2.launch.py` 第一版建议支持这些 launch 参数：

| 参数 | 目的 |
| --- | --- |
| `use_sim_time` | 仿真必须使用 `/clock` |
| `params_file` | 指向 `nav2_params.yaml` |
| `use_slam` | 是否使用在线 SLAM |
| `map` | 静态地图路径，仅 `use_slam:=false` 时使用 |
| `autostart` | 是否自动激活 lifecycle 节点 |

是否把 Gazebo、SLAM 和 Nav2 合成一个总 launch，可以等本阶段链路跑通后再决定。

## 暂不建议修改的文件

| `src/kibot_one_sim/models/follow_flag/model.sdf` | 阶段 02 不处理旗帜 |
| `src/kibot_one_sim/worlds/kibot_one.world.sdf` | 第一版优先在障碍物 world 验证 |
