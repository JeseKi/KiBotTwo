# 阶段 02：Nav2 接口契约

## 契约定位

本文件定义阶段 02 对阶段 03 暴露的最小导航接口。

阶段 03 的 frontier 探索模块不应直接控制 `/cmd_vel`，而应把探索目标转换成 Nav2 goal。

## 主要 action

阶段 03 调用：

```text
/navigate_to_pose
```

类型：

```text
nav2_msgs/action/NavigateToPose
```

## goal frame

第一版目标点使用：

```text
map
```

原因：

- frontier 提取基于 occupancy grid。
- occupancy grid 的 frame 预期是 `map`。
- Nav2 global planner 以 `map` 作为 global frame。

## goal 最小字段

阶段 03 至少需要提供：

```text
pose.header.frame_id = "map"
pose.header.stamp = 当前 ROS time
pose.pose.position.x
pose.pose.position.y
pose.pose.position.z = 0.0
pose.pose.orientation = 目标朝向
```

第一版 orientation 可采用：

- 朝向目标方向。
- 或单位四元数，表示不强调最终朝向。

最终采用哪种方式由阶段 03 根据探索行为决定。

## 导航结果

阶段 03 至少需要区分：

| 状态 | 处理方式 |
| --- | --- |
| 成功 | 标记当前 frontier 已到达，继续选择下一个 |
| 失败 | 标记当前 frontier 不可达或降权 |
| 取消 | 当前目标被新任务替代，不当作地图失败 |
| 超时 | 主动 cancel goal，并降权当前 frontier |

具体状态码以 Nav2 action result 为准，本阶段只要求验证能观测到成功和失败路径。

## 取消当前目标

阶段 03 必须能取消当前 goal。

触发条件可能包括：

- 视觉检测已经发现旗帜。
- frontier 已不再有效。
- 导航长时间无进展。
- 任务状态机切换到停止或靠近状态。

## 不暴露的接口

阶段 02 不向阶段 03 暴露：

- `/cmd_vel`
- Nav2 内部 planner plugin API。
- costmap 内部 topic 作为控制入口。
- 旧 FOLLOW 模式 topic。

这些内部细节可以用于调试，但不作为探索模块的主接口。

## 阶段 03 依赖的可观测性

阶段 02 应记录以下可观测点：

- `/navigate_to_pose` action 是否存在。
- 当前 goal 是否被接受。
- 当前 goal 是否完成、失败或取消。
- Nav2 是否正在发布 `/cmd_vel_raw`，以及 `cmd_vel_watchdog` 是否正在转发到 `/cmd_vel`。
- costmap 是否因为障碍物或未知区域拒绝目标点。

如果这些信息无法稳定观测，阶段 03 的 frontier 策略会难以调试。
