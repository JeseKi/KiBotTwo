# 01-隔离旧控制链路

## 本节目标

让 Nav2 的速度输出成为 02 阶段唯一的机器人运动来源，避免旧的 FOLLOW、MANUAL、CRUISE 控制链路和 Nav2 同时发布速度。

## 为什么现在做

当前项目已有 `mode_control`、`follow_controller` 和 `cmd_vel_watchdog`。它们通过 `/cmd_vel_raw -> /cmd_vel` 控制机器人。如果 Nav2 与这些节点同时运行，导航结果会被旧控制器覆盖或相互竞争。

## 需要参考

- `../reference/control-ownership.md`

## 具体做法

1. 不复用 `kibot_one.launch.py` 作为 Nav2 主入口。
2. 新增独立的 `nav2.launch.py`。
3. `nav2.launch.py` 只启动 Gazebo、bridge、SLAM 和 Nav2。
4. 不启动 `mode_control`、`follow_controller`、`keyboard_teleop` 或 `cmd_vel_watchdog`。
5. 让 Nav2 的 `/cmd_vel_smoothed` 由 bridge 转发到 Gazebo DiffDrive。

## 做完应该看到什么

`ros2 launch kibot_one_sim nav2.launch.py --show-args` 中能看到 Nav2 参数，但不会出现旧控制节点的启动参数。
