# 03-接通 Nav2 启动链路

## 本节目标

本节编写：

```text
src/kibot_one_sim/launch/nav2.launch.py
```

它的职责不是“再包一层 launch”，而是把阶段 02 的运行组合固定下来：

```text
Gazebo + ros_gz_bridge
  -> slam_toolbox
  -> nav2_bringup navigation stack
  -> 可选 RViz
```

阶段 03 的探索模块应该只需要启动这一个入口，而不是手工拼多个终端。

## 为什么现在做

Nav2 依赖 `/clock`、TF、`/odom`、`/scan` 和 `/map`。如果这些组件每次由用户手工启动，验证结果就会随启动顺序变化。

一个统一入口可以把这些运行假设写成代码：

- 默认启动障碍物世界。
- 默认让 Gazebo 立即运行。
- 默认启动 SLAM。
- 默认启动 Nav2。
- 默认检查 Nav2/FastCDR 依赖。

本节需要参考：

- `../reference/dependencies.md`
- `../reference/file-plan.md`

## 第一步：建立 launch 文件骨架

先写最小文件：

```python
from launch import LaunchDescription


def generate_launch_description() -> LaunchDescription:
    return LaunchDescription([])
```

这一步只证明文件是一个合法 ROS2 launch 文件。此时运行：

```bash
ros2 launch kibot_one_sim nav2.launch.py --show-args
```

不会看到任何参数，因为我们还没有声明参数。

## 第二步：找到需要复用的 package 路径

Nav2 launch 需要引用两个 package：

- `kibot_one_sim`：当前项目的 world、SLAM launch、Nav2 参数。
- `nav2_bringup`：官方 navigation stack launch 和 RViz 配置。

先加入 import：

```python
from pathlib import Path

from ament_index_python.packages import get_package_share_directory
from launch import LaunchDescription
```

然后在 `generate_launch_description()` 里拿到 share 目录：

```python
def generate_launch_description() -> LaunchDescription:
    sim_pkg_share = Path(get_package_share_directory("kibot_one_sim"))
    nav2_bringup_share = Path(get_package_share_directory("nav2_bringup"))

    return LaunchDescription([])
```

这里使用 `get_package_share_directory()`，是因为安装后文件不一定还在源码目录。ROS2 launch 应该从 package share 目录寻找资源。

接下来把本节需要的文件路径写出来：

```python
default_world = sim_pkg_share / "worlds" / "kibot_one_obstacles.world.sdf"
sim_with_bridge_launch = sim_pkg_share / "launch" / "sim_with_bridge.launch.py"
slam_launch = sim_pkg_share / "launch" / "slam.launch.py"
nav2_navigation_launch = nav2_bringup_share / "launch" / "navigation_launch.py"
nav2_rviz_config = nav2_bringup_share / "rviz" / "nav2_default_view.rviz"
nav2_params = sim_pkg_share / "config" / "nav2_params.yaml"
```

这些变量还没有启动任何东西，只是把运行组合的文件入口集中在一起。

## 第三步：先声明最核心的参数

现在加入 launch 参数相关 import：

```python
from launch.actions import DeclareLaunchArgument
```

先声明 world：

```python
world_arg = DeclareLaunchArgument(
    name="world",
    default_value=str(default_world),
    description="Gazebo 世界文件的绝对路径。",
)
```

这让用户可以在不改代码的情况下切换 world：

```bash
ros2 launch kibot_one_sim nav2.launch.py world:=/abs/path/to/world.sdf
```

再声明 Nav2 参数文件：

```python
params_file_arg = DeclareLaunchArgument(
    name="params_file",
    default_value=str(nav2_params),
    description="Nav2 参数文件路径。",
)
```

这一步的意义是：调参时可以传入另一份 YAML，不需要复制 launch 文件。

最后把它们放进 `LaunchDescription`：

```python
return LaunchDescription([
    world_arg,
    params_file_arg,
])
```

此时运行：

```bash
ros2 launch kibot_one_sim nav2.launch.py --show-args
```

应该至少能看到 `world` 和 `params_file`。

## 第四步：加入仿真时间和 lifecycle 参数

Nav2 在仿真里必须使用 sim time：

```python
use_sim_time_arg = DeclareLaunchArgument(
    name="use_sim_time",
    default_value="true",
    description="Nav2 是否使用仿真时间。",
)
```

Nav2 lifecycle 是否自动激活，由 `autostart` 控制：

```python
autostart_arg = DeclareLaunchArgument(
    name="autostart",
    default_value="true",
    description="是否自动激活 Nav2 lifecycle nodes。",
)
```

如果 `autostart` 是 `false`，Nav2 节点可能启动了但不进入 active，`/navigate_to_pose` 也不能正常执行目标。

再加入组合节点和 respawn 参数：

```python
use_composition_arg = DeclareLaunchArgument(
    name="use_composition",
    default_value="False",
    description="是否使用 Nav2 组合节点容器。",
)
use_respawn_arg = DeclareLaunchArgument(
    name="use_respawn",
    default_value="False",
    description="Nav2 节点退出后是否自动重启。",
)
```

阶段 02 默认不使用 composition 和 respawn，是为了调试时每个节点和日志更清楚。

## 第五步：把 Gazebo 和 bridge 包进来

现在加入 Include 相关 import：

```python
from launch.actions import IncludeLaunchDescription
from launch.conditions import IfCondition
from launch.launch_description_sources import PythonLaunchDescriptionSource
from launch.substitutions import LaunchConfiguration
```

先声明是否启动仿真：

```python
start_sim_arg = DeclareLaunchArgument(
    name="start_sim",
    default_value="true",
    description="是否同时启动 Gazebo 和 ros_gz_bridge。",
)
```

再声明 Gazebo 是否启动后立即运行：

```python
run_on_start_arg = DeclareLaunchArgument(
    name="run_on_start",
    default_value="true",
    description="是否使用 -r 让 Gazebo 启动后立即运行仿真。",
)
```

`run_on_start:=true` 很重要。Gazebo 如果停在暂停状态，`/odom` 和 TF 不会稳定推进，Nav2 lifecycle 激活会变得不可靠。

现在包含 `sim_with_bridge.launch.py`：

```python
start_sim = IncludeLaunchDescription(
    launch_description_source=PythonLaunchDescriptionSource(str(sim_with_bridge_launch)),
    launch_arguments={
        "world": LaunchConfiguration("world"),
        "run_on_start": LaunchConfiguration("run_on_start"),
    }.items(),
    condition=IfCondition(LaunchConfiguration("start_sim")),
)
```

这一段有三个点：

- `PythonLaunchDescriptionSource` 指向另一个 launch 文件。
- `launch_arguments` 把当前入口的 `world` 和 `run_on_start` 透传下去。
- `condition` 让用户可以用 `start_sim:=false` 只测 Nav2 参数。

## 第六步：把 SLAM 包进来

先声明开关：

```python
start_slam_arg = DeclareLaunchArgument(
    name="start_slam",
    default_value="true",
    description="是否同时启动 slam_toolbox。",
)
```

阶段 01 的 SLAM launch 还支持补齐激光静态 TF，所以也透传这个参数：

```python
use_lidar_static_tf_arg = DeclareLaunchArgument(
    name="use_lidar_static_tf",
    default_value="true",
    description="透传给 slam.launch.py，用于补齐 base_link -> lidar_link。",
)
```

然后包含 SLAM：

```python
start_slam = IncludeLaunchDescription(
    launch_description_source=PythonLaunchDescriptionSource(str(slam_launch)),
    launch_arguments={
        "use_lidar_static_tf": LaunchConfiguration("use_lidar_static_tf"),
    }.items(),
    condition=IfCondition(LaunchConfiguration("start_slam")),
)
```

这一步完成后，`map -> odom -> base_link` 这条链路才有机会完整出现。

## 第七步：把 Nav2 navigation stack 包进来

先声明是否启动 Nav2：

```python
start_nav2_arg = DeclareLaunchArgument(
    name="start_nav2",
    default_value="true",
    description="是否启动 Nav2 navigation stack。",
)
```

再声明日志等级：

```python
log_level_arg = DeclareLaunchArgument(
    name="log_level",
    default_value="info",
    description="Nav2 日志等级。",
)
```

现在包含 `nav2_bringup` 的 `navigation_launch.py`：

```python
start_nav2 = IncludeLaunchDescription(
    launch_description_source=PythonLaunchDescriptionSource(str(nav2_navigation_launch)),
    launch_arguments={
        "use_sim_time": LaunchConfiguration("use_sim_time"),
        "autostart": LaunchConfiguration("autostart"),
        "params_file": LaunchConfiguration("params_file"),
        "use_composition": LaunchConfiguration("use_composition"),
        "use_respawn": LaunchConfiguration("use_respawn"),
        "log_level": LaunchConfiguration("log_level"),
    }.items(),
    condition=IfCondition(LaunchConfiguration("start_nav2")),
)
```

这里没有手动启动 `controller_server`、`planner_server` 等节点，而是交给 Nav2 官方 bringup。这样阶段 02 只维护 KiBotTwo 的参数和组合方式，不复制 Nav2 内部启动逻辑。

## 第八步：加入可选 RViz

RViz 不是自动验收必需项，所以默认关闭。

先加 import：

```python
from launch_ros.actions import Node
```

声明参数：

```python
use_rviz_arg = DeclareLaunchArgument(
    name="use_rviz",
    default_value="false",
    description="是否启动 RViz Nav2 默认视图。",
)
```

再启动 RViz：

```python
start_rviz = Node(
    package="rviz2",
    executable="rviz2",
    name="rviz2",
    output="screen",
    arguments=["-d", str(nav2_rviz_config)],
    parameters=[{"use_sim_time": LaunchConfiguration("use_sim_time")}],
    condition=IfCondition(LaunchConfiguration("use_rviz")),
)
```

这让用户可以这样启动可视化：

```bash
ros2 launch kibot_one_sim nav2.launch.py use_rviz:=true
```

自动验证时建议用 `use_rviz:=false`，减少变量。

## 第九步：启动前检查 Nav2 运行依赖

之前遇到过 FastCDR 符号缺失，表现为 Nav2 节点运行时崩溃。这个问题不是 YAML 能修的，所以放进 launch 前置检查。

先加入 import：

```python
import subprocess
from launch.actions import OpaqueFunction
```

写一个最小检查函数：

```python
def _check_nav2_runtime_deps(context, *args, **kwargs):
    fastcdr_lib = Path("/opt/ros/jazzy/lib/libfastcdr.so.2")
    if not fastcdr_lib.exists():
        raise RuntimeError("未找到 libfastcdr.so.2")
    return []
```

这里先只检查文件存在。接下来用 `nm` 检查符号：

```python
result = subprocess.run(
    ["bash", "-lc", f"nm -D {fastcdr_lib} 2>/dev/null | c++filt"],
    check=False,
    capture_output=True,
    text=True,
)
if "eprosima::fastcdr::Cdr::serialize(unsigned int)" not in result.stdout:
    raise RuntimeError("FastCDR 缺少 Cdr::serialize(unsigned int)")
```

这段检查对应历史失败：

```text
undefined symbol: eprosima::fastcdr::Cdr::serialize(unsigned int)
```

最后加一个开关：

```python
check_runtime_deps_arg = DeclareLaunchArgument(
    name="check_runtime_deps",
    default_value="true",
    description="启动前是否检查 Nav2/FastCDR 运行库兼容性。",
)
check_runtime_deps = OpaqueFunction(function=_check_nav2_runtime_deps)
```

如果用户只是看参数，可以关闭它：

```bash
ros2 launch kibot_one_sim nav2.launch.py --show-args
```

如果依赖真的坏了，launch 应该在 Nav2 启动前失败，并提示先修依赖。

## 第十步：把所有 action 放进 LaunchDescription

最终的返回列表按“参数声明在前，运行 action 在后”的顺序组织：

```python
return LaunchDescription([
    world_arg,
    params_file_arg,
    use_sim_time_arg,
    autostart_arg,
    use_composition_arg,
    use_respawn_arg,
    log_level_arg,
    start_sim_arg,
    run_on_start_arg,
    start_slam_arg,
    start_nav2_arg,
    use_lidar_static_tf_arg,
    use_rviz_arg,
    check_runtime_deps_arg,
    check_runtime_deps,
    start_sim,
    start_slam,
    start_nav2,
    start_rviz,
])
```

这个顺序方便阅读：先告诉用户有哪些开关，再执行依赖检查，再启动各组件。

## 做完应该看到什么

先看参数：

```bash
ros2 launch kibot_one_sim nav2.launch.py --show-args
```

应该能看到：

```text
world
params_file
use_sim_time
autostart
start_sim
run_on_start
start_slam
start_nav2
use_rviz
check_runtime_deps
```

再启动：

```bash
ros2 launch kibot_one_sim nav2.launch.py use_rviz:=false
```

如果依赖缺失，先修依赖，不要继续调 Nav2 参数。如果 launch 正常启动，下一节开始验证 lifecycle、action、速度链路和目标执行。

## 本节小结

本节把阶段 02 的运行组合收束成一个入口：

```text
nav2.launch.py
```

它不复用旧控制入口，不手写 Nav2 内部节点，而是组合已有仿真、阶段 01 SLAM 和 Nav2 bringup。
