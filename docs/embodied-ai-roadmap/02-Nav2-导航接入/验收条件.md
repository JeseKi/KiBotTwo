# 阶段 02：验收条件

## 验收目标

本阶段的验收重点是确认 Nav2 已经成为“给定目标点即可导航”的稳定执行层。

验收不要求导航参数最优，也不要求探索行为自动发生。只要目标点来自 RViz 或 action client，Nav2 能规划、控制并反馈结果，就可以解锁 `03-边界探索`。

## 进入条件

进入功能实现前，阶段 01 至少应满足：

| 前置项 | 要求 |
| --- | --- |
| `/map` | 能发布 `nav_msgs/msg/OccupancyGrid`，或已有可加载地图 |
| `map -> odom` | 可用且无明显跳变 |
| `odom -> base_link` | 可用 |
| `base_link -> lidar_link` | 可用 |
| `/scan` | 能转换到 robot base frame |
| `/cmd_vel` | 能驱动 Gazebo 小车 |

如果这些前置项没有文档记录，本阶段可以继续写配置计划，但不能判定为功能完成。

## 必须通过的功能验收

| 验收项 | 要求 | 备注 |
| --- | --- | --- |
| Nav2 可启动 | lifecycle 相关节点能启动 | 允许先手动 lifecycle bringup |
| Nav2 active | 核心节点进入 active | 至少包含 planner、controller、bt_navigator、costmap |
| costmap 可用 | local/global costmap 正常发布 | RViz 可见 |
| 地图可用 | global costmap 能基于 `map` 工作 | 在线 SLAM 或静态地图均可 |
| TF 可用 | Nav2 不报 TF timeout 或 frame mismatch | 偶发启动时延需记录 |
| action 可用 | `/navigate_to_pose` 能接收 goal | RViz 或 CLI 均可 |
| 规划可用 | 目标点可生成 path | 简单场景即可 |
| 控制可用 | Nav2 controller 向 `/cmd_vel_raw` 输出，并经 `cmd_vel_watchdog` 转发到 `/cmd_vel` | 需要确认没有旧节点抢占 `/cmd_vel_raw` |
| 机器人运动 | 小车实际响应导航命令 | 不只看 topic |
| 失败反馈可见 | 不可达目标能返回失败或取消状态 | 供阶段 03 使用 |

## 控制链路验收

Nav2 验证时必须明确 `/cmd_vel_raw` 和 `/cmd_vel` 的发布者。

合格状态：

- Nav2 controller 是主要 `/cmd_vel_raw` 发布者。
- `cmd_vel_watchdog` 是 `/cmd_vel` 发布者，并把 Nav2 输出转发给 Gazebo bridge。
- `follow_controller` 未参与导航验证。
- `keyboard_teleop` 未参与导航验证。
- `mode_control` 在 `NAV2` 模式下不会持续覆盖 Nav2 输出。
- `cmd_vel_watchdog` 不会导致正常导航中反复刹停。

如果需要暂时关闭或调整 `cmd_vel_watchdog`，应把原因和启动方式记录到 `记录与复盘.md`。

## costmap 验收

第一版 costmap 验收标准：

- global costmap 中能看到地图占据区域。
- local costmap 中能看到激光障碍物。
- robot footprint 或 robot radius 与小车尺寸大致一致。
- 障碍物不会全部被当作可通行区域。
- 未知区域策略明确记录为允许或不允许穿越。

不要求：

- inflation 半径一次调到最优。
- 所有障碍物边界完全平滑。
- 所有狭窄区域都能通过。

## 导航行为验收

至少完成以下三类验证：

| 场景 | 目标 |
| --- | --- |
| 近距离无遮挡目标 | 验证 controller、`/cmd_vel_raw` 和 `/cmd_vel` 链路 |
| 简单绕障目标 | 验证 planner 和 costmap 基本有效 |
| 不可达目标 | 验证失败反馈能被阶段 03 使用 |

每类验证记录：

- 启动命令。
- goal 所在 frame。
- goal 大致位置。
- 结果：成功、失败、取消或卡住。
- 失败时的关键日志。

## 对阶段 03 的解锁条件

进入 `03-边界探索` 前，必须明确：

- 探索模块应该调用哪个 action，预期是 `/navigate_to_pose`。
- goal 使用哪个 frame，预期是 `map`。
- goal message 最小字段是什么。
- 如何判断导航成功。
- 如何判断导航失败或超时。
- 如何取消当前 goal。
- frontier 目标点不应直接写 `/cmd_vel`。

## 不通过条件

如果出现以下任一情况，本阶段不能结束：

- Nav2 节点不能进入 active。
- costmap 无法发布或 frame 错误。
- `NavigateToPose` goal 无法被接收。
- Nav2 不产生 `/cmd_vel_raw` 且原因不明。
- `/cmd_vel_raw` 被旧控制节点持续覆盖且没有隔离方案。
- 小车完全不响应 Nav2 输出。
- 阶段 03 无法得知如何发送目标点或处理失败。

## 允许遗留的问题

以下问题可以记录后留到后续阶段，不阻塞阶段 02 完成：

- 导航路径不够平滑。
- controller 参数需要继续调优。
- 局部避障偶尔保守。
- 是否把导航文件迁移到独立 package。
- 是否引入 `velocity_smoother`。
- 是否保存静态地图作为固定测试输入。
