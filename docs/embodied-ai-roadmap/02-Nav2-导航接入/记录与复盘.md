## 决策记录

### D-02-001：Nav2 文件归属

状态：建议采用。

决策：

- 阶段 02 先把 `nav2.launch.py` 和 `nav2_params.yaml` 放在 `kibot_one_sim`。

原因：

- 当前仿真、bridge、SLAM 文件都在 `kibot_one_sim`。
- 阶段 02 的重点是跑通导航链路，不是 package 分层。
- 阶段 03 引入探索节点时再考虑拆出 `kibot_one_navigation`。

### D-02-002：阶段 03 调用方式

状态：建议采用。

决策：

- 阶段 03 通过 `/navigate_to_pose` action 调用 Nav2。
- 阶段 03 不直接发布 `/cmd_vel`。

原因：

- Nav2 负责 planner、controller、costmap 和失败反馈。
- 探索模块只负责选择目标点。
- 这能让边界探索和底层运动控制解耦。

### D-02-003：地图来源

状态：待运行时确认。

候选：

- 在线 SLAM + Nav2。
- 静态地图 + Nav2。

当前倾向：

- 先用在线 SLAM + Nav2 承接阶段 01。
- 如果 lifecycle、TF 或 costmap 排查复杂，再保存静态地图做 Nav2 最小验证。
