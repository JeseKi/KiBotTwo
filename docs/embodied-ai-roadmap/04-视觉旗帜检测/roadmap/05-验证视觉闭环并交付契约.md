# 05 验证视觉闭环并交付契约

## 本节目标

确认阶段 04 的完整链路可运行：

```text
Gazebo camera -> /camera/image_raw -> flag_detector -> /flag_detection
```

前四节分别完成了接口、相机、算法和节点接线。最后这一节把它们放回同一个 ROS2/Gazebo 系统里验证，并把阶段 05、阶段 06 可以依赖的内容讲清楚。

## 构建

先激活环境：

```bash
source .vscode/project-terminal-init.sh
```

构建三个受影响 package：

```bash
colcon build --packages-select kibot_one_interface kibot_one_control kibot_one_sim
```

期望结果：

- `kibot_one_interface` 能生成 `FlagDetection`。
- `kibot_one_sim` 能安装修改后的 model 和 bridge 配置。
- `kibot_one_control` 能安装 `flag_detector` 和 launch 文件。

## 跑核心算法测试

阶段 04 把算法层设计成纯函数，因此这里用直接 pytest 命令验证算法契约：

```bash
python -m pytest -q src/kibot_one_control/test/test_frontier_core.py src/kibot_one_control/test/test_flag_detection_core.py
```

期望结果：

- 既有 frontier core 测试仍通过。
- 新增红色检测核心测试通过。

如果 `colcon test --packages-select kibot_one_control` 返回 `NO TESTS RAN`，它表示当前包的 pytest 发现方式还没有接入 `colcon test`。本阶段先以直接 pytest 命令验收算法层，后续可以单独整理测试集成配置。

## 启动视觉检测 launch

运行：

```bash
ros2 launch kibot_one_control flag_detection.launch.py start_sim:=true run_on_start:=true
```

在另一个终端检查 topic：

```bash
source .vscode/project-terminal-init.sh
ros2 topic list
```

至少应该看到：

```text
/camera/image_raw
/flag_detection
```

`/flag_pose` 也可能存在，但它只是 debug 对照，不属于阶段 04 的 mission 输入。

## 读取检测消息

继续运行：

```bash
ros2 topic echo --once /flag_detection
```

成功消息应该类似：

```text
header:
  frame_id: camera_link
detected: true
center_x: 44.15916061401367
center_y: 31.16216278076172
image_width: 320
image_height: 240
pixel_count: 333
confidence: 0.0043359375558793545
```

数值不必完全一样；重要的是：

- `header.frame_id` 来自相机。
- `detected=true` 时中心点落在图像范围内。
- 输出没有 `map`、`world` 或 `/flag_pose` 坐标。

这一步验证的是事件语义，而不是某一次仿真的精确像素值。只要消息来自相机帧、中心点合理、内容保持在图像观测范围内，就满足阶段 04 对后续章节的交付要求。

## 交付给阶段 05 的契约

阶段 05 可以把图像中心转成方向误差：

```text
horizontal_error = center_x - image_width / 2
vertical_error = center_y - image_height / 2
```

距离估计由阶段 05 承担，可以选择深度相机、单目尺寸估计或只做方向对齐。

这正好把下一章的问题收束清楚：阶段 04 告诉系统“旗帜在图像里的哪里”，阶段 05 再决定如何从图像位置走向机器人运动所需的空间估计。

## 交付给阶段 06 的契约

阶段 06 可以先实现“发现即停止”：

```text
if /flag_detection.detected:
    cancel current exploration goal
    publish zero velocity or switch to STOP
```

状态机应该自行处理多帧去抖，例如连续 N 帧 detected 后才切换，或 detected=false 后延迟恢复探索。本阶段只发布逐帧观测。

这样任务状态机可以保持独立：视觉节点负责感知事实，状态机负责把多帧观测转成任务决策。

## 本阶段完成后解锁

- `05-旗帜位置估计`：可以使用图像像素质心和检测质量继续做方向或位置估计。
- `06-任务状态机`：可以消费 `/flag_detection.detected`，先实现发现即停止。
