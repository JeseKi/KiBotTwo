# 01 定义视觉检测事件

## 本节目标

先在 `kibot_one_interface` 中新增 `FlagDetection` 消息。这个消息是阶段 04 的核心交付物：它告诉后续任务状态机“当前相机帧是否看到旗帜”，但不提供 Gazebo 的全局真值。

## 为什么先做接口

视觉节点、任务状态机和后续位置估计都会围绕这个消息协作。先固定接口，后面的相机和算法只需要回答如何填充这些字段。

这一节承接阶段 03 的探索能力：探索负责移动到未知区域，视觉事件负责告诉系统“相机这一帧看到了什么”。接口先稳定下来，后续章节就能分别实现相机输入、颜色检测和 ROS2 节点，而不会在模块之间反复改字段。

## 新增消息文件

创建 `src/kibot_one_interface/msg/FlagDetection.msg`：

```text
std_msgs/Header header
bool detected
float32 center_x
float32 center_y
uint32 image_width
uint32 image_height
uint32 pixel_count
float32 confidence
```

字段设计理由：

- `header` 沿用图像 header，让消费者知道检测来自哪个相机 frame。
- `detected` 给阶段 06 提供最小状态切换条件。
- `center_x` / `center_y` 给阶段 05 留出方向估计入口。
- `image_width` / `image_height` 让消费者能把像素中心归一化。
- `pixel_count` / `confidence` 用来判断检测质量。

这些字段有意保持在图像平面内。这样阶段 04 可以专注完成“看见旗帜”的事件，阶段 05 再在同一个事件上继续推导方向或位置。

## 注册消息生成

打开 `src/kibot_one_interface/CMakeLists.txt`。在已有 `find_package(geometry_msgs REQUIRED)` 下方增加：

```cmake
find_package(std_msgs REQUIRED)
```

然后在 `rosidl_generate_interfaces` 中把新消息放到已有消息之前：

```cmake
rosidl_generate_interfaces(${PROJECT_NAME}
  "msg/FlagDetection.msg"
  "msg/Mode.msg"
  "msg/ModeState.msg"
  "srv/Mode.srv"
  DEPENDENCIES geometry_msgs std_msgs
)
```

这里把 `std_msgs` 加进 `DEPENDENCIES`，是因为 `FlagDetection.msg` 使用了 `std_msgs/Header`。

## 更新 package 依赖

打开 `src/kibot_one_interface/package.xml`。在已有 `geometry_msgs` 依赖附近增加：

```xml
  <depend>std_msgs</depend>
```
